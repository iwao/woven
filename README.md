# WOVEN App

Interactive visual and sonic client for WOVEN. It consumes versioned, prepared assets generated by the adjacent `woven-data` repository.

The app must not depend directly on the ClassiiDB PostgreSQL database or large source JSONL files.

## Artist artwork routes

`scripts/build_artwork_catalog.py` creates a bounded public catalogue from the
highest cumulative Artist relation weights. It exposes routes in the form
`/artists/<classii-id>/<slug>/<year>`. The immutable Classii entity ID resolves
the artwork; the slug is a readable alias and is canonicalised by the app.

```sh
python3 scripts/build_artwork_catalog.py --limit 100
```

`public/_redirects` is the static-host rewrite rule for `/artists/*` so a direct
visit is served by the application rather than a filesystem 404.

## Social previews / OGP

`scripts/build_artwork_ogp.py` exports crawlable HTML documents and 1200 × 630
PNG social-preview images from the same prepared Artist/Work vectors used by the
canvas. It defaults to the current artwork year for each public Artist, keeping
the deploy payload bounded while covering the normal individual-artwork links.

```sh
python3 scripts/build_artwork_ogp.py --site-url https://your-woven-domain.example
```

The command writes static pages below `artists/<classii-id>/<slug>/<year>/` and
their PNGs below `public/og/artworks/`. Static pages take precedence over the
SPA fallback in `public/_redirects`; routes not prerendered remain interactive
through that fallback. Use `--years active` to export every year in which one of
the 100 public Artists acquires vectors (rather than only its default year).

For a local server without route rewrites, the equivalent artwork view can be
opened with `/?artist=<classii-id>&slug=<slug>&year=<year>`.

## Sample prototype

Build the compact browser asset and sparse LOD pixel tiles after generating the
WOVEN sample outputs:

```sh
python3 scripts/import_sample_assets.py --suffix artist_first_1000_artists
python3 ../woven-data/src/build_artist_lod_pixel_tiles.py \
  --relations ../woven-data/output/artist_work_relations_artist_first_1000_artists.jsonl \
  --artist-order ../woven-data/output/artist_dimension_order_artist_first_1000_artists.jsonl \
  --artist-tree ../woven-data/output/artist_lod_tree_artist_first_1000_artists.jsonl \
  --vectors ../woven-data/output/artist_year_vectors_artist_first_1000_artists.jsonl \
  --output-dir public/data/woven-tiles \
  --snapshot-id classii-3a1d5ce-artist-first-20261005
python3 -m http.server 4173 --bind 127.0.0.1
```

Open `http://localhost:4173`. The X axis is the complete Artist population and
semantic zoom switches it between overview clusters, intermediate clusters, and
individual Artists. The Y axis has two non-compressed entity layers:
Work-mediated related Artists and individual Works. In the all-Artist view, each
LOD layer is rendered from a corresponding sparse pixel matrix. Each pixel stores
temporal deltas, so the year control accumulates it without rebuilding the
complete relation graph. Density comes from the growing cross count, while
relation weight is encoded by gold brightness. Choosing an Artist switches to its
precise entity-level relations for focus and inspection,
and offers an opt-in Web Audio beat.
